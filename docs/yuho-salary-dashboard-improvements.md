# 有報年収ダッシュボード 改善提案（Claude Code 向け）

対象サイト: https://yuho-salary-dashboard.vercel.app/
作成目的: Claude Code に実装を依頼するための改善タスク一覧（優先順位・根拠・完了条件つき）

## 現状サマリ

- 構成: トップ / ランキング / 業界別 / 企業を探す / トレンド / 企業詳細(約4,000社) / 比較(vs) / 偏差値チェッカー
- データソース: 金融庁 EDINET の有価証券報告書（平均年間給与・従業員数・平均年齢・勤続年数・役員報酬・業績 等）
- 直近7日の Google Search Console:
  - クリック 5 / 表示 263 / 平均CTR 1.9% / 平均掲載順位 10.6

### 所見（前提）

- プログラマティックSEOの「骨格」は良い。企業×4,000・業界×34・比較ページ・独自指標（役員報酬/1人あたり売上/女性管理職比率/勤続×年収）まで揃っており、クチコミ年収主体の大手（OpenWork・就活会議・転職会議 等）にない差別化がある。
- 一方で **流入のボトルネックは「収益化」ではなく「インデックスされる土台」と「信頼性(YMYL)」** にある。表示263回/週は、大半のページがインデックスされていない状態を示唆する。
- 年収・転職は YMYL（Your Money or Your Life）領域で、Google の E-E-A-T 評価が厳しい。データの正確性・運営者の透明性が順位の前提になる。

| # | 施策 | 種別 | 効果 | 工数感 |
|---|------|------|------|--------|
| 1 | 集計企業数の不整合バグ修正 | データ/信頼性 | 高 | 小 |

## 1. 集計企業数の不整合バグ修正【最優先】

### 課題
集計企業数がページごとに食い違っている。

- トップ: 収録企業数 4,069社 / うち上場 4,102社（※上場数が総数を超えており論理破綻）
- ランキング: 全4,053社
- トレンド: 4,053社
- 業界別: 全2,926社

### 根拠
YMYLサイトで同一サイト内の母数が4通り存在するのは、E-E-A-T（信頼性）を直接損なう。データサイトの生命線。

### 変更内容
- 集計対象の定義を1つに確定（例: 「最新の有報を取得できた上場企業」）し、母数を単一の値として全ページで参照する。
- 件数は集計ロジックから動的に算出し、ハードコードを排除（ページ間でズレない設計にする）。
- 「収録企業数」と「うち上場」の意味を定義し直し、矛盾（上場 > 総数）を解消。

### 完了条件
- トップ / ランキング / トレンド / 業界別 / 企業を探す の全ページで企業数が一致する。
- 「うち上場」が総数を超えない。

## 2. 業界ページで全社掲載＝内部リンク開通【SEO最重要】

### 課題
- ランキングは上位200社しかリンクしていない。
- 業界ページは各業界とも8社しか表示していない（例: 情報・通信は403社あるのに8社のみ）。
- 結果、約4,000社のうち大半が「どこからもリンクされない孤島ページ」になっている可能性が高い。クローラが到達できず、インデックスされない。

### 根拠
表示263回/週という数字は、4,000ページを作っても数十ページしか認識されていないことを示唆する。プログラマティックSEOは「全ページに到達可能な内部リンク網」があって初めて機能する。

### 変更内容
- 業界詳細ページ（`/industries/{業界}`）で、その業界の全社を一覧表示（ページネーション or 無限スクロールではなくページネーション推奨。クローラビリティ重視）。
- ランキングも200社で打ち切らず、ページネーションで全社到達可能にする（`/ranking?page=2` 等、クロール可能なリンク構造）。
- `sitemap.xml` に全企業ページ・全比較ページ・全業界ページを含める。動的生成し、ビルドごとに更新。
- 企業詳細ページ同士の相互リンク（同業他社・vs ページ）は既にあるので維持・拡充。

### 完了条件
- 任意の企業詳細ページに、トップから「業界一覧 → 業界詳細 → 企業」のリンクで到達できる。
- sitemap に全 indexable ページが含まれる。
- （実装後）GSC の「インデックス登録済みページ数」が数十→数千オーダーに増える。

## 3. 未分類データのクリーンアップ

### 課題
- 業界「-」（未分類）に企業が紛れ込み、`/industries/-` のような不正なURL/ページが生成されている。

### 変更内容
- 業界が取得できない企業は名寄せ・再分類、または一覧から除外し、`/industries/-` を生成しない。
- 業界マスタを整備し、表記ゆれ（全角/半角、「・」区切り等）を正規化。

### 完了条件
- 全企業に有効な業界が割り当たる、または未分類は明示的に「その他」へ集約。
- 不正URL（`/industries/-` 等）が存在しない。

---

## 4. 独自ドメイン + 運営者情報 + 集計方法ページ【YMYL の土台】

### 課題
- `*.vercel.app` サブドメイン運用。独自ドメインの権威が蓄積されにくく、YMYL では順位の頭打ち要因になる。
- 運営者・集計方法の透明性が乏しい（E-E-A-T 不足）。

### 変更内容
- 独自ドメインへ移行（取得後、301でリダイレクト or 早期に切替）。
- 「運営者情報」ページ: 運営主体・連絡先・サイトの目的。
- 「データについて / 集計方法」ページ: 出典（EDINET）、対象範囲、平均年収の定義（単体・正社員の平均年間給与である旨）、更新頻度、注意事項。
- 全ページのフッター/メタに canonical を正しく設定（独自ドメイン基準）。
- OGP / sitemap / robots の URL を独自ドメインに統一。

### 完了条件
- 独自ドメインで配信され、旧URLが新URLへ恒久リダイレクト。
- 運営者情報・集計方法ページが存在し、フッターから到達可能。

## 5. 独自指標ランキングの独立ページ化

### 課題
役員報酬・従業員1人あたり売上高・女性管理職比率・勤続年数×年収 などの独自指標は、現状は企業詳細ページ内に埋もれている。大手競合が弱い「勝てる長尾」を取りこぼしている。

### 変更内容
独立したランキング/まとめページを新設（各ページに集計の独自テキストを1〜2文添える＝thin content回避）:

- `/ranking/executive-pay` 役員報酬ランキング
- `/ranking/sales-per-employee` 従業員1人あたり売上高ランキング
- `/ranking/female-managers` 女性管理職比率ランキング
- `/ranking/long-tenure` 勤続年数が長い高年収企業
- `/ranking/young-high-income` 若手×高年収（平均年齢が若い高年収企業）

各ページは業界・規模フィルタを共通化し、企業詳細への内部リンクを持たせる（2の内部リンク網も兼ねる）。

### 完了条件
- 上記ランキングページが生成され、相互リンク・企業詳細リンクを持つ。
- sitemap に含まれる。

---

## 6. 偏差値チェッカーのシェア導線強化（SEOに依存しない流入）

### 課題
ドメインが弱い間、検索順位は時間がかかる。一方、偏差値チェッカーは拡散型の資産になり得るが、シェア設計が弱い。

### 変更内容
- 診断結果に動的OG画像を生成（「あなたの年収偏差値 ◯◯ / 上場企業中 上位◯%」）。企業詳細では既にOG画像を生成しているので、その仕組みを診断結果にも展開。
- 結果ページに固有URL（クエリ or パス）を付与し、X / LINE シェアボタンを設置。
- 「同年収帯の企業はここ」など、診断後に企業詳細・ランキングへ誘導する導線を追加（回遊とアフィリ導線を兼ねる）。

### 完了条件
- 診断結果がシェア可能なURL＋OG画像を持つ。
- 結果からランキング/企業詳細への内部リンクがある。

## 7. アフィリエイトの実装整備（収益化・コンプライアンス）

### 課題
企業詳細に doda / リクナビNEXT / ビズリーチ への求人検索リンクは設置済みだが、計測・表記・規約面の整備が要る。

### 変更内容
- アフィリンクに `rel="sponsored nofollow"` を付与。
- リンク周辺に PR表記（「PR」「広告」等）を明示（景表法のステマ規制対応）。
- リンクの計測（クリックイベント）を入れ、後で効果検証できるようにする。
- ※ディスプレイ広告（AdSense等）は、自動生成データの独自性審査・単価の両面から、流入が育ってからにする。

### 完了条件
- 全アフィリンクに rel と PR表記が付く。
- クリック計測が動作する。

## UI / UX 所見

> 注意: ページの実描画（色・余白・タイポ・レスポンシブ）は今回取得できず、抽出テキストとサイト構造からの推測です。見た目そのものの評価が必要な場合はスクリーンショットを共有してください。

構造から指摘できる範囲:

1. **情報の欠落が「UIの不親切さ」として表面化している**（最大のUX問題）
   - 業界ページが各8社のみ。「403社」と表示しながら8社しか出さないのは、ユーザーに「データが少ない」誤認を与える。施策2の全社掲載はSEOだけでなくUX改善でもある。
   - ランキングが200社で止まり「続きを見る」導線がない。

2. **数字の不整合は、見た目以前に信頼を損なう**
   - 同じサイトで母数が4通り（施策1）。ユーザーが複数ページを見ると気づく。データサイトの第一印象を直接下げる。

3. **回遊導線の設計余地**
   - 偏差値チェッカー（強い体験）→ ランキング/企業詳細 への誘導が弱い。診断後に「あなたと同水準の企業」などの導線を入れると滞在・回遊が伸びる（施策6）。
   - 企業詳細の「同業他社比較」「vs ◯◯」は良い導線。各ページからランキング/業界ページへ戻る導線も明示すると回遊が安定する。

4. **YMYLとしての表示の丁寧さ**
   - 「平均年収＝単体・正社員の平均年間給与」である旨を、企業詳細にも一言キャプションで明示すると、誤解（残業/賞与込みか等）を防げて信頼が上がる。
   - データの「対象期（◯年◯月期）」「出典」は既に出ていて良い。全ページで統一を。

5. **モバイル**（要スクショ確認）
   - ランキングの表組み・業界カードの横スクロール挙動など、モバイルでの可読性は実機/スクショで確認したい。年収系は検索流入の多くがモバイルになるため重要。

## Claude Code への依頼テンプレ（コピペ用）

> 以下の優先順で改修してほしい。各タスクは「完了条件」を満たすこと。
> 1. 集計企業数の不整合を修正（全ページで母数を単一ロジックから算出。上場数が総数を超えないように）。
> 2. 業界ページとランキングを全社掲載（ページネーション）にして、全企業詳細へ内部リンクが到達するようにする。sitemap.xml を動的生成し全 indexable ページを含める。
> 3. 業界未分類（`/industries/-` 等）をクリーンアップ。
> 4. 独自ドメイン対応（canonical/OGP/sitemap/robots のURL統一）＋運営者情報・集計方法ページを新設。
> 5. 独自指標ランキング（役員報酬/1人あたり売上/女性管理職比率/勤続×年収/若手高年収）を独立ページ化。
> 6. 偏差値チェッカーの結果に固有URL＋動的OG画像＋シェアボタンを実装し、結果からランキング/企業詳細へ誘導。
> 7. アフィリンクに rel="sponsored nofollow" とPR表記を付与し、クリック計測を入れる。

## 確認したい事項（着手前）

- **GSC のインデックス登録済みページ数は現在いくつか？** 数十なら施策2が最優先、数千入っているなら施策4・5（順位改善側）に寄せる。
- 独自ドメインは取得済みか（移行の可否）。
- アフィリエイトは各サービスの提携審査を通過済みか（リンク形式の制約確認のため）。
